# Data model

Everything the widget stores or emits. Source of truth: `src/types.ts`.

## `AnnotationRecord`

The full schema. This is what lives in `localStorage` (`Store`), what `CloudStore` writes to Postgres, and what `Export` dumps to JSON.

```ts
interface AnnotationRecord {
  // Identity
  id: string;                  // UUID (crypto.randomUUID, fallback timestamp+random)
  projectName: string;         // Namespace key. From data-project / config.
  message: string;             // Reviewer's comment body.
  authorName: string;          // From localStorage; "Anonymous" if unset.
  url: string;                 // Full URL with sensitive query params stripped (token/key/secret/auth/session/password/code).
  path: string;                // Normalized location.pathname (no trailing slash, no query/hash).
  viewport: string;            // "1280x800" — the reviewer's window inner size at capture time.
  userAgent: string;           // navigator.userAgent verbatim.
  createdAt: string;           // ISO-8601 UTC timestamp.

  // Lifecycle
  status?: "todo" | "done" | "question";   // Default "todo".
  kind?: "target" | "pin" | "area";        // Default "target".

  // DOM anchor (target kind primarily; populated for all kinds, empty strings for pin/area)
  cssSelector: string;         // Generated by @medv/finder.
  xpath: string;               // Direct DOM path.
  textSnippet: string;         // First ~500 chars of textContent.
  elementTag: string;          // UPPERCASE tag name (e.g. "BUTTON").
  elementId?: string;          // Element's id attribute, if any.
  textPrefix: string;          // Text immediately before the element.
  textSuffix: string;          // Text immediately after the element.
  fingerprint: string;         // Tag-chain ancestry signature.
  neighborText: string;        // Sibling/cousin text snapshot.

  // Position relative to anchor element bounding box (target kind)
  xPct: number;                // 0..1 — fraction of anchor width.
  yPct: number;                // 0..1 — fraction of anchor height.
  wPct: number;                // 0..1 — fraction of anchor width.
  hPct: number;                // 0..1 — fraction of anchor height.

  // Viewport-absolute coords (pin kind)
  pinX?: number;               // Document-coordinate x (window.scrollX-aware).
  pinY?: number;               // Document-coordinate y.

  // Viewport-absolute rect (area kind)
  areaX?: number;
  areaY?: number;
  areaW?: number;
  areaH?: number;

  // Captured DOM context (pin / area kinds — for handoff to AI agents or devs)
  capturedElements?: CapturedElement[];
}

interface CapturedElement {
  tag: string;                                                     // Lowercase tag.
  attributes: Record<string, string>;                              // All HTML attrs.
  rect: { x: number; y: number; w: number; h: number };            // Bounding box at capture time.
}
```

## Annotation kinds

| Kind     | Anchor                  | Position                                   | Use case                                                  |
| -------- | ----------------------- | ------------------------------------------ | --------------------------------------------------------- |
| `target` | DOM element             | `xPct/yPct/wPct/hPct` of element rect      | "This button has the wrong copy."                         |
| `pin`    | Viewport coordinate     | `pinX/pinY` (document-relative)            | "Something feels off in this whitespace."                 |
| `area`   | Viewport rectangle      | `areaX/areaY/areaW/areaH`                  | "This whole hero section needs to breathe more."          |

`pin` and `area` kinds populate `capturedElements` with snapshots of whatever DOM was under/inside the marker at capture time, so a developer (or an AI agent) reading the export still has DOM context even though the pin isn't anchored to a specific element.

## URL sanitization

`src/index.ts > sanitizeUrl()` strips query params whose **key** matches `/token|key|secret|auth|session|password|code/i` before the URL is stored. This is best-effort PII protection — it's not exhaustive, and reviewers shouldn't pin from URLs that contain credentials in the first place.

Path / hash / non-matching query params are preserved.

## `localStorage` shape

Records are stored as a JSON array under one key per project:

```
key:    ccm-feedback:<projectName>
value:  [AnnotationRecord, AnnotationRecord, ...]
```

Newest first (`unshift`). On quota-exceeded, writes silently drop — no eviction policy.

## Postgres shape (`ccm_widget_annotations`)

Same fields, snake_case. See `supabase/migrations/0001_init.sql` for column definitions and `0002_status_pin_area.sql` for the status/kind/pin/area additions.

PostgREST → record mapping lives in `src/cloud-store.ts > rowToRecord()` / `recordToRow()`.

## Export JSON shape

`src/export-utils.ts > exportAsJson()` serializes the current store contents (filtered to one project) to a JSON file:

```json
{
  "projectName": "my-site",
  "exportedAt": "2026-05-08T12:34:56.789Z",
  "count": 42,
  "annotations": [
    { "id": "...", "message": "...", ... }
  ]
}
```

Filename: `ccm-feedback-<projectName>-<YYYY-MM-DD>.json`.

This is the canonical handoff format. A developer or agent receiving the file gets every signal needed to:

- Re-locate each pin in the current DOM (via the four-strategy resolver)
- Reproduce the reviewer's viewport and URL context
- Understand what was selected (`capturedElements` for non-target kinds)
